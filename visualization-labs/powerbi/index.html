Power BI — Create an empty Measures table first

Why do this? A dedicated table keeps DAX measures together rather than scattering them across FactAdmissions, FactHousingProjects, or unrelated dimension tables. It makes the model easier to maintain and makes every calculation easier to find. This is an organizational table: do not create relationships from it.

  1. Finish loading your CSV tables, then switch from Power Query to the main Power BI Desktop window.
  2. On the Home ribbon, choose Enter data. A small Create Table window appears.
  3. Keep the initial grid empty (do not enter a business data record). In the Name box at the bottom, enter _Measures, then select Load. Power BI creates a table with a placeholder Column1.
  4. In the Data pane, right-click _Measures and choose New measure. Enter your first DAX measure, for example Total Admissions = COUNTROWS(FactAdmissions) for healthcare or Total Budget = SUM(FactHousingProjects[BudgetAllocated]) for housing. Press Enter.
  5. Repeat right-click _Measures → New measure for each DAX measure in your chosen lab. Copy and create each formula separately; multiple measures pasted into one formula bar will not work.
  6. Right-click the placeholder Column1 and choose Hide in report view (or Hide, depending on the version). It remains a harmless technical column, but it will not clutter the report authoring pane.
  7. If you accidentally created a measure under a fact table, select that measure and use Measure tools → Home table → _Measures to move its organizational home. This does not change the measure's calculation.
  8. Optional but recommended: select a measure and under Properties → Display folder organize it into 01 | Activity, 02 | Outcomes, or 03 | Financials. Use separate folder names for each lab as appropriate.
  9. Save your .pbix file and take a screenshot showing _Measures expanded with the calculator icons next to your measures.
Visual checkpoint: The Data pane contains _Measures with calculator-marked items such as Total Admissions, ALOS, and Readmission Rate or Total Budget, Total Spent, and Utilization %. The placeholder column is hidden. There is no relationship line linking _Measures to the star schema.
Teaching distinction: A measure returns a result based on the current filter context and belongs in _Measures. A calculated column computes a value for each row and stays in its real data table. Therefore, Age Group and Risk Level remain in DimPatient; HousingCalendar is a separate calculated table, not a measure.
Should _Measures be connected to FactAdmissions or FactHousingProjects in Model view?

Healthcare C — Create measures and calculated columns

In the Data pane right-click _Measures → New measure. Paste one measure at a time from the block below; these are separate expressions. Click the measure, then use Measure tools to format rates as percentages, ALOS to two decimal places, and cost as currency.

Total Admissions = COUNTROWS(FactAdmissions)

ALOS = AVERAGE(FactAdmissions[LengthOfStay])

Readmission Count =
CALCULATE(
    COUNTROWS(FactAdmissions),
    FactAdmissions[ReadmissionFlag] = 1
)

Readmission Rate =
DIVIDE([Readmission Count], [Total Admissions], 0)

Avg Cost per Patient = AVERAGE(FactAdmissions[Cost])

Age Group =
SWITCH(
    TRUE(),
    DimPatient[Age] < 18, "Pediatric (0-17)",
    DimPatient[Age] < 65, "Adult (18-64)",
    "Senior (65+)"
)

Risk Level =
IF(DimPatient[ChronicCondition] = "None", "Low Risk", "High Risk")

For Age Group and Risk Level, right-click DimPatient → New column (these two are columns, not measures).

Expected overall checks: Admissions 500; average stay 3.83 days; readmission rate 11.60%; average cost $12,728.15. These overall results assume no filters.

Why: AVERAGE divides total stay days by the number of nonblank stays. CALCULATE changes filter context; DIVIDE safely handles a zero denominator. Rates must be stored as fractions (e.g., 0.2) and displayed as percentages.

Healthcare D — Correctly compare admissions with discharges

  1. In Model view choose Manage relationships → New. Link DimDate[Date] to FactAdmissions[DischargeDate], with Active unchecked; keep the admission-date relationship active.
  2. Right-click _Measures and create the discharge measure below using New measure.
  3. Insert a Line chart. Drag DimDate[Date] onto the X-axis (select Date, not its automatic hierarchy if individual dates are needed).
  4. Put both Total Admissions and Total Discharges in Y-axis. Choose a month grouping for an executive-level trend, or daily dates to inspect gaps.
  5. Verify the date table covers admission and discharge dates. Because both are in 2024, the supplied healthcare calendar covers the series.
Total Discharges =
CALCULATE(
    COUNTROWS(FactAdmissions),
    USERELATIONSHIP(DimDate[Date], FactAdmissions[DischargeDate])
)
A net difference in daily admission and discharge counts is not, by itself, proof of bed blocking. It is a signal to investigate occupancy, available beds, and discharge delays; those additional measures are not contained in the provided CSVs.

Healthcare E — Create and arrange every required visual

  1. Create four Card visuals. Assign Total Admissions, ALOS, Readmission Rate, Avg Cost per Patient. Set clear titles and appropriate number formats.
  2. Create Line chart: X = DimDate[Date]; Y = Total Admissions and Total Discharges.
  3. Create Clustered bar chart: Y = DimDoctor[Department]; X = Readmission Rate. Add a constant/reference line at 0.219 when the measure is a fraction formatted as 21.9%. Label this as the assignment’s illustrative benchmark rather than verified current national performance.
  4. Create Matrix: Rows = DimDate[DayOfWeek]; Columns = DimDate[Month]; Values = Total Admissions. Under Cell elements/conditional formatting apply background-color gradient. Sort month using MonthNum and weekdays chronologically if desired.
  5. Create Decomposition tree: Analyze = ALOS (not raw sum of LengthOfStay); Explain by = Department, Age Group, InsuranceProvider, ChronicCondition. Expand nodes to investigate longer stays.
  6. Create Treemap: Group = DimDoctor[Specialty]; Values = Readmission Count. Remember a specialty with more admissions may also have more readmissions; examine rates as well as counts.
  7. Add slicers for dates and Department. Test that clicking one department appropriately updates other visuals.
  8. In the Data pane hide patient name and IDs from report authors to reduce accidental use, and create only aggregate visuals. Hiding fields is not a privacy or access-control guarantee. Avoid publishing any identifiable patient data publicly.
  9. Capture a full-screen dashboard screenshot including KPI cards, a trend, a heat map/tree, and specialty comparison.
Dashboard composition: four KPI cards in the top band; admissions/discharges and department comparisons in the middle; matrix, decomposition tree, and specialty analysis below. Use two pages if chart labels become unreadable.

Housing A — Prepare the public administration dataset

⬇ FactHousingProjects.csv⬇ DimWard.csv⬇ DimFundingSource.csv⬇ DimDate.csv
  1. Create MG628_Housing_Dashboard.pbix. Choose Get data → Text/CSV → Transform Data for each downloaded CSV.
  2. Rename the queries FactHousingProjects, DimWard, DimFundingSource, DimDate.
  3. Confirm budgets and spending are Decimal Number/Currency-compatible; IDs are Text; dates are Date; poverty measures use the units present in the data.
  4. Critical quality check: The housing project StartDate begins in July 2023, but the supplied DimDate only covers calendar 2024. A direct relationship would hide some 2023 records in date-filtered views.
  5. Create an expanded date table in Power BI after Close & Apply using Modeling → New table and the expression below. Use the resulting HousingCalendar instead of the incomplete supplied DimDate in the relationship.
HousingCalendar =
ADDCOLUMNS(
    CALENDAR(
        MIN(FactHousingProjects[StartDate]),
        MAX(FactHousingProjects[ExpectedEndDate])
    ),
    "CalendarYear", YEAR([Date]),
    "MonthNum", MONTH([Date]),
    "Month", FORMAT([Date], "MMMM"),
    "FiscalYear", "FY" & FORMAT(YEAR(EDATE([Date], 6)), "0000")
)
This calculated table requires correctly typed date columns. The fiscal-year expression uses a July–June fiscal year. If your instructor requires a different fiscal-year label convention, state it explicitly. The 2024 source DimDate is retained for comparison and data-quality teaching.
Expected: 74 projects, 12 wards, 10 funding sources. Confirm the calendar includes every StartDate.

  3. Connect HousingCalendar[Date] to FactHousingProjects[StartDate].
  4. Check every link uses a dimension-side unique key and Single filter direction. Capture a model screenshot.
  5. Right-click _Measures → New measure. Enter each of the measures below one at a time. Format currency and percentages.
Total Budget = SUM(FactHousingProjects[BudgetAllocated])

Total Spent = SUM(FactHousingProjects[BudgetSpent])

Utilization % = DIVIDE([Total Spent], [Total Budget], 0)

Units Created = SUM(FactHousingProjects[UnitsCreated])

Units Target = SUM(FactHousingProjects[UnitsTarget])

Units Completion % = DIVIDE([Units Created], [Units Target], 0)

Project Count = DISTINCTCOUNT(FactHousingProjects[ProjectID])

Projects At Risk =
CALCULATE(
    [Project Count],
    FactHousingProjects[Status] IN {"Delayed", "On Hold"}
)

Budget Per Capita =
DIVIDE([Total Budget], SUM(DimWard[Population]), 0)
Equity modeling caution: Budget Per Capita is meaningful at each ward and the unfiltered whole-city level. In a total across an arbitrary cross-filtered grouping, SUM(DimWard[Population]) may include wards outside the current project subset depending on filter directions. Use a ward-level visual and validate the grouping denominator carefully.
Unfiltered expected totals: Budget $145,860,000.00; Spent $79,937,212.94; Utilization 54.80%; Units 985 of 1,919.

Housing C — Build the budget-transparency executive report

  1. Top row: make Cards for Total Budget, Utilization %, Units Created, Projects At Risk. Add a Ward slicer.
  2. Insert a Gauge with Value = Utilization %, minimum = 0, maximum = 1, target = 1. Ensure the displayed formatting is percent.
  3. Insert a Clustered bar: Y = DimWard[WardName]; X = Total Budget and Total Spent. Sort by Total Budget descending.
  4. Insert a Line and clustered column chart: X = WardName; column = Budget Per Capita; line = PovertyRate. If poverty values are stored as 0–100 rather than 0–1, do not apply percent formatting without normalization. Use a secondary axis and label units.
  5. Insert a Scatter chart: X = DimWard[MedianIncome] (do not sum income across wards); Y = Budget Per Capita; Details = WardName (use category/values field appropriate to your Power BI version); Size = Population if helpful. Ensure there is one mark per ward, not one aggregated dot.
  6. Insert a Decomposition tree: Analyze = Total Budget; Explain by = WardName, ProjectType, funding Category and Status.
  7. Insert a Treemap: Group = WardName, Details = Status, Values = Project Count. Alternatively, a stacked bar is easier for comparing category proportions.
  8. Insert a Donut: Legend = DimFundingSource[Category]; Values = Total Budget. Give it the title “Budget allocations by funding category” (not total financing capacity).
  9. Insert a Clustered bar comparing Units Target and Units Created by ProjectType. Add interactions with the Ward slicer.
  10. Capture screenshots and write a city-manager memo: identify equity concerns, separate observed correlation from causal claims, and recommend two defensible actions supported by data.
