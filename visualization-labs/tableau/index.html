Tableau lab orientation

This laboratory translates your Tableau lecture workflow into practice: Connect → Prepare → Relate → Calculate → Visualize worksheets → Assemble Dashboard → Explain decisions.

Use Tableau Desktop or a compatible Tableau Public authoring environment. Interface labels can differ slightly by release. For privacy, do not upload identifiable patient or customer contact data to Tableau Public. Use local Tableau Desktop for nonpublic data or prepare a de-identified aggregate dataset before public sharing.

Submission: a packaged Tableau workbook .twbx when available, a dashboard screenshot and an evidence/interpretation document. Public publishing is optional and appropriate only for approved nonsensitive data.

Tableau A — Connect to customer segmentation data

⬇ Customer_Segmentation_Data.csv⬇ Customer_data.xlsx
  1. Open Tableau and under Connect → To a File choose Text File, then Customer_Segmentation_Data.csv.
  2. On the Data Source page confirm field names Customer_ID, Age, Gender, Annual_Income, Spending_Score, Region, and Loyalty_Status.
  3. Inspect data types: Customer_ID = String/Dimension, Age = Whole Number, Annual_Income and Spending_Score = Number, Region and Loyalty_Status = String. Click the type icon to correct a field.
  4. Set an extract if your authoring environment requires it; select Sheet 1 at the bottom to begin.
  5. Rename the sheet Customer Overview. Observe Tableau’s Dimensions (categories) and Measures (quantities).
Verify 100 customer rows; mean income approximately $66,574.52; mean spending 43.86 in an unfiltered view.
Which field belongs naturally on Color to compare loyalty groups?

Tableau B — Calculated fields and customer quadrants

From the left Data pane drop-down or Analysis → Create Calculated Field, create each field separately. Use exactly the field names from the CSV, including underscores.

// Calculated Field name: Income Band
IF [Annual_Income] >= 70000 THEN "High Income"
ELSE "Lower Income"
END

// Calculated Field name: Spend Band
IF [Spending_Score] >= 50 THEN "High Spend"
ELSE "Lower Spend"
END

// Calculated Field name: Customer Quadrant
[Income Band] + " / " + [Spend Band]

// Calculated Field name: Premium Loyalty
IF [Loyalty_Status] = "Gold" OR [Loyalty_Status] = "Platinum"
THEN 1 ELSE 0 END

// Calculated Field name: Premium Share
AVG([Premium Loyalty])
The threshold 70,000 and spending cutoff 50 are instructional segmentation choices, not discovered optimal cutoffs. Revisit them if the lecture prescribes alternative quadrant definitions. Format Premium Share as Percent.
  1. Create a new worksheet called Segmentation Matrix. Drag Customer Quadrant to Rows.
  2. Drag Customer_ID to Text on the Marks card, then change the pill aggregation to Count (Distinct) if IDs are unique.
  3. Add Region to Filters, then right-click the filter and select Show Filter.
  4. Explain the difference between a measure (aggregated based on the view) and a row-level calculated field (evaluated per customer).

Tableau C — Build the customer dashboard worksheet by worksheet

  1. KPI / BAN: New sheet; drag Customer_ID to Text on Marks and choose COUNTD. Increase text size. Duplicate for AVG(Annual_Income), AVG(Spending_Score) and Premium Share.
  2. Income histogram: Right-click Annual_Income → Create → Bins; choose a bin size such as 10,000. Drag Income (bin) to Columns, Number of Records (or COUNT Customer_ID) to Rows, choose Bar.
  3. Income vs spending scatter: Columns = Annual_Income, Rows = Spending_Score. Change each aggregation or add Customer_ID to Detail to create one mark per person. Place Loyalty_Status on Color and Region on Filters.
  4. Loyalty bar chart: Loyalty_Status to Rows; COUNTD(Customer_ID) to Columns; sort descending; enable mark labels.
  5. Regional heat map: Region to Rows, Loyalty_Status to Columns; count of customers to Color and Label on a Square Marks type.
  6. Quadrant comparison: Customer Quadrant to Columns; COUNTD(Customer_ID) to Rows; annotate which high-income customers score below the spending threshold.
If a scatter plot shows one dot, Tableau is aggregating data. Place Customer_ID on Detail to disaggregate to customer level, or uncheck Analysis → Aggregate Measures with care.

Tableau D — Analyze retail store operations

⬇ Stores.xlsx
  1. From the Tableau start page connect to Microsoft Excel and choose Stores.xlsx. Drag the Stores sheet into the Data Source canvas.
  2. Verify the fields StoreKey, StoreType, Status, OpenDate, CloseDate, EmployeeCount and SellingAreaSize.
  3. Inspect nulls in ZipCode and CloseDate. A blank CloseDate does not necessarily mean bad data: many stores are still operating. Do not delete entire records indiscriminately.
  4. Make a KPI showing COUNTD(StoreKey). Make a horizontal bar chart with StoreType on Rows and COUNTD(StoreKey) on Columns; place Status on Color.
  5. Create an operational efficiency view: StoreType on Rows, AVG(SellingAreaSize) on Columns, and count on Label. Explain why average store size differs from total selling area.
  6. Make a time trend: RIGHT-click OpenDate → Year, drag to Columns; COUNTD(StoreKey) to Rows. Use Exact Date/month if deeper detail is desired.
Expected store records: 306. This workbook contains a geographical key but not an explicit City/State field; do not assume Tableau can map GeographyKey to a real location without a separate geography lookup.

Tableau E — Relate healthcare tables without duplicating admissions

⬇ FactAdmissions.csv⬇ DimPatient.csv⬇ DimDoctor.csv⬇ DimDate.csv
  1. Connect to Text File → FactAdmissions.csv. On the Data Source page add each remaining CSV through the data connections area.
  2. At the logical (top) level of the Data Source canvas, drag DimPatient near FactAdmissions and select Relationship, not an indiscriminate physical join. Set PatientID = PatientID.
  3. Relate DimDoctor[DoctorID] to FactAdmissions[DoctorID].
  4. Relate DimDate[Date] to FactAdmissions[AdmissionDate] after ensuring both are Date types.
  5. Inspect a worksheet with count of admission IDs and verify it remains 500. If counts change, inspect the relationships, key type, and aggregation.
  6. Create the calculations below by using Analysis → Create Calculated Field.
// Calculated Field name: Admission Count
COUNTD([AdmissionID])

// Calculated Field name: Average Length of Stay
AVG([LengthOfStay])

// Calculated Field name: Readmission Rate
SUM(INT([ReadmissionFlag])) / COUNT([AdmissionID])

// Calculated Field name: Average Admission Cost
AVG([Cost])

// Calculated Field name: Age Group
IF [Age] < 18 THEN "Pediatric (0-17)"
ELSEIF [Age] < 65 THEN "Adult (18-64)"
ELSE "Senior (65+)" END
Verify 500 admission records, mean stay 3.83, and readmission rate 11.60% before filtering.
In Tableau, aggregations across logically related tables depend on their relationship and level of detail. Check the 500-admission total before using these expressions. Never publicly publish names or other patient identifiers.

Tableau F — Assemble a hospital analytics dashboard

  1. Make KPI worksheets using Admission Count, Average Length of Stay, Readmission Rate and Average Admission Cost; format percentages, currency, and decimal places.
  2. Build admissions by month: AdmissionDate (MONTH) to Columns; Admission Count to Rows; Marks = Line. Confirm months are ordered chronologically.
  3. Build department performance: Department to Rows; Readmission Rate to Columns; Marks = Bar. Add a reference line only if the instructor-supplied benchmark is relevant to your sampled population; the 21.9% number in the source is an exercise reference, not a verified current all-admission standard.
  4. Build length of stay by age group: Age Group to Rows and Average Length of Stay to Columns. Sort by the measure.
  5. Build readmissions by specialty: Specialty to Rows; SUM(ReadmissionFlag) to Columns, noting this compares volumes rather than risk-adjusted rates.
  6. Use Dashboard → New Dashboard. Set a fixed canvas size such as 1200 × 850 or Automatic for responsive display. Drag worksheets into tiled containers: KPIs top, trend middle, comparisons below.
  7. For a common Department or date filter: on the worksheet filter menu select Apply to Worksheets → All Using Related Data Sources only after checking the relationship setup.
  8. On the dashboard select a visual and choose Use as Filter; click a department and verify the KPI values change as expected.
  9. Write a decision note explaining what admissions, stay length, and readmissions indicate — and what the dataset cannot establish about actual bed availability.

Tableau G — Public housing equity and funding dashboard

⬇ FactHousingProjects.csv⬇ DimWard.csv⬇ DimFundingSource.csv⬇ DimDate.csv
  1. Connect to FactHousingProjects.csv. Add DimWard.csv and DimFundingSource.csv as logical relationships: WardID and FundID respectively.
  2. For dates, do not use the provided housing DimDate for all historical analysis: it covers 2024 only while StartDate begins in 2023. Use StartDate directly for date-based worksheets, or generate a full calendar externally before relating it.
  3. Verify Count Distinct of ProjectID = 74. Create the following separate Tableau calculated fields.
// Calculated Field name: Total Budget
SUM([BudgetAllocated])

// Calculated Field name: Total Spent
SUM([BudgetSpent])

// Calculated Field name: Utilization Rate
IF SUM([BudgetAllocated]) = 0 THEN 0
ELSE SUM([BudgetSpent]) / SUM([BudgetAllocated]) END

// Calculated Field name: Units Completion Rate
IF SUM([UnitsTarget]) = 0 THEN 0
ELSE SUM([UnitsCreated]) / SUM([UnitsTarget]) END

// Calculated Field name: Ward Population LOD
{ FIXED [WardID] : MIN([Population]) }

// Calculated Field name: Budget Per Capita (Ward)
IF MIN([Ward Population LOD]) = 0 THEN 0
ELSE SUM([BudgetAllocated]) / MIN([Ward Population LOD]) END
LOD teaching point: Ward Population LOD fixes population at the WardID level. FIXED LOD calculations may ignore ordinary dimension filters unless made context filters. Always inspect selected-ward totals and compare against the ward table before drawing conclusions.
  1. Create a budget bar chart: WardName to Rows, Total Budget to Columns. Add Total Spent as a second bar or a dual-axis comparison with clearly differentiated labels.
  2. Create a budget per capita bar chart by WardName; verify each ward’s denominator is its own population.
  3. Create an equity scatter plot: MedianIncome to Columns, Budget Per Capita (Ward) to Rows, WardName to Detail, PovertyRate to Color. Ensure exactly one mark per ward and appropriate aggregation.
  4. Create a funding mix bar/donut view by funding Category and SUM(BudgetAllocated). Create a project status stacked bar by WardName and Status.
  5. Build a dashboard with KPI sheets, ward equity comparison, funding mix and at least one interactive Ward filter.
  6. Write a memo identifying which wards appear underserved, whether spending utilization differs, and two justified resource-allocation recommendations.

Tableau H — Publish responsibly and package your workbook

  1. Save your working Tableau workbook frequently (File → Save As).
  2. Open Dashboard → New Dashboard. For each selected scenario, drag 4 KPI worksheets and 3–5 analytical worksheets into balanced containers.
  3. Add informative titles and dynamic filters. Choose a consistent format for currency, rate and date measures.
  4. Use the dashboard’s Use as Filter control to connect selections; test at least two filters and reset them after testing.
  5. Use File → Export as Image/PDF where supported, or capture a readable screenshot.
  6. When working in Tableau Desktop, use File → Export Packaged Workbook or Save As with Tableau Packaged Workbook (.twbx) for portability. Test reopening the packaged file.
  7. Avoid sharing customer contact records or patient names through Tableau Public. If publishing is approved, use a non-identifying or aggregate extract and inspect the published data source.
Quality criteria: (1) all numbers agree with base tables; (2) one logical filter updates related visuals; (3) no unintentional duplicated joins; (4) each chart answers a concrete business question; (5) written recommendations acknowledge limitations.
