1. From Raw Data to a Managerial Decision

In everyday language: what are we doing this week?

Imagine a hospital administrator or city manager receives several spreadsheets with hundreds of rows. The rows are useful, but nobody can make a quick decision by staring at them. Your job is to turn those rows into a few trustworthy numbers and pictures that answer a real question.

Think of a dashboard like the dashboard in a car: it does not show every engine part. It shows the few signals the driver needs right now—speed, fuel, warning lights—so the driver can decide what to do.

Where Power BI fits: Power BI is the software that helps you connect the files, calculate the important numbers, and arrange those numbers into interactive charts and cards.

A dashboard is useful only when every layer is defensible. Week 6 connects the work you have already done in the course.

Week 6 rule: Data → measure → visual → interpretation → action. If any link is weak, the dashboard can mislead even when it looks professional.

2. Model & Visual Grammar

Before Power BI terms, picture a filing system

You have one list of events—for example, every hospital admission or every housing project. Then you have smaller reference lists that explain who, where, when, or what those events refer to.

The event list is what Power BI calls a fact table. The reference lists are dimension tables. A relationship simply tells Power BI which ID connects the lists.

A fact table is like a stack of receipts. A dimension table is like the customer, product, doctor, ward, or calendar directory that explains what the codes on each receipt mean.

Power BI modeling grammar

ElementRole
Fact tableEvents at the declared grain
DimensionWho / what / where / when descriptors
RelationshipDefines how filters reach fact rows
MeasureDynamic calculation under filter context
SlicerUser-controlled filter

Visualization grammar

QuestionUseful visual
Compare categoriesBar chart
Show change over timeLine chart
Show two-variable relationshipScatter plot
Show intensity across two dimensionsHeatmap / matrix
Show hierarchical compositionTreemap
Teaching moment: Choosing a visual is not an artistic decision first. It is an analytical decision about the comparison the manager must make.

4A. Healthcare Administration — Patient Flow & Readmission Assignment Prep

Your assignment in plain English

You are acting like a hospital analyst preparing information for leadership. The hospital wants to know: Are patients moving through the hospital efficiently? Are too many coming back within 30 days? Which departments deserve attention?

You will not answer those questions by reading 500 admission rows one by one. You will connect the admission records to patient, doctor, and date information, calculate a few important measures, and then build visuals that make patterns easy to see.

Power BI connection: first build the model, then create the calculations, then place those calculations into charts. That order matters.

Your formal assignment asks you to build a Power BI model and dashboard around patient flow, readmissions, throughput, cost, staffing, and clinical performance.

How participation maps to the graded assignment

  1. Q1: Load four tables and build the healthcare star schema.
  2. Q2: Create Average Length of Stay and validate it with a card and department comparison.
  3. Q3: Build the 30-day Readmission Rate and compare departments with the benchmark.
  4. Q4: Build Total Admissions and a time trend.
  5. Q5: Build Average Cost per Patient and compare departments.
  6. Q6: Build the required operational visuals, including heatmap/deep-dive analysis.
  7. Q7: Assemble the dashboard and slicers.
  8. Q8: Write a CMO memo using specific evidence and recommendations.
FactAdmissions
This is your main event list. One row means one hospital admission.
DimPatient / DimDoctor / DimDate
These are reference lists. They help you answer “which patient group?”, “which department?”, and “when?” without repeating all of that descriptive information in every admission row.
DAX measure
This is a formula Power BI recalculates when you filter the dashboard. If you click Surgery, the same Readmission Rate formula should recalculate for Surgery only.
Slicer
This is a visible filter button for the report user. It is like saying “show me only Cardiac Care” or “show me September.”
  1. Load the four CSV files and check the row counts.
  2. Connect the ID fields so Power BI knows which descriptive row belongs to each admission.
  3. Create the measures: admissions, average stay, readmission rate, and average cost.
  4. Place each measure into the chart that best answers the assignment question.
  5. Filter and test the dashboard. The KPI should change logically when you select a department or date.
  6. Write the CMO memo from the evidence—not from assumptions.

4B. Public Administration (MPA) — Housing & Budget Transparency Assignment Prep

Your assignment in plain English

You are acting like an analyst in a city manager's office. The city has promised housing investment, but leaders need to know two things: Are we actually spending the money, and is the investment reaching communities with the greatest need?

A large budget number alone cannot answer that. You must connect projects to wards, funding sources, and dates; calculate spending and housing-output measures; and then compare investment with community need.

Power BI connection: the dashboard should help a city manager move from “How much did we spend?” to “Where did it go, what did it produce, and is the pattern equitable?”

Your formal assignment asks you to build a Power BI model and dashboard showing resource deployment, housing delivery, geographic equity, project status, and funding risk.

How participation maps to the graded assignment

  1. Q1: Load four tables and build the housing star schema.
  2. Q2: Create the five accountability measures and validate utilization/per-capita funding.
  3. Q3: Build the income-versus-investment equity scatter plot.
  4. Q4: Compare housing-unit completion by project type.
  5. Q5: Visualize the funding-source mix.
  6. Q6: Analyze project status and delayed/on-hold work.
  7. Q7: Assemble the complete dashboard with ward filtering.
  8. Q8: Write a City Manager policy memo with evidence and measurable recommendations.
FactHousingProjects
This is the project list. One row means one housing project with budget, spending, units, dates, and status.
DimWard
This explains the neighborhood context—population, income, poverty, and other characteristics used to interpret equity.
Budget utilization
This asks, “Of the money we approved, how much have we actually spent?” It is spending divided by budget.
Budget per capita
This asks, “How much investment is assigned per resident?” It lets you compare wards of different population sizes more fairly.
  1. Load the project, ward, funding-source, and date files.
  2. Connect WardID, FundID, and StartDate so the model can group projects correctly.
  3. Create the five accountability measures before building visuals.
  4. Use bars for ward comparisons, a scatter plot for income versus investment, and composition visuals for funding/status.
  5. Test the ward slicer and make sure every KPI and chart responds consistently.
  6. Write the policy memo from measured gaps and completion evidence—not from political assumptions.

5. Power BI → Tableau Transfer

Do not memorize buttons—learn the analytical idea

Power BI and Tableau use different menus and vocabulary, but the underlying reasoning is the same. If “Department” is a category in Power BI, it is still a category in Tableau. If Readmission Rate means readmissions divided by all admissions, that definition cannot change just because the software changes.

Think of Power BI and Tableau like two different calculators. The buttons may be in different places, but 58 ÷ 500 should not produce a different answer.

The formal graded assignments are Power BI based. The supplied Tableau walkthroughs are valuable because they show that the analytical question survives a change in software.

Power BI

Model → DAX measure → visual field wells → slicers/filter context.

Tableau

Relationships → dimensions/measures → Rows/Columns → Marks → filters.

Transfer principle: Department remains a category, ALOS remains an average, and the readmission denominator remains all admissions regardless of which visualization application you use.

6. Accuracy, Relevance & Dashboard Critique

A beautiful chart can still be wrong

A dashboard is only as trustworthy as the data and calculations underneath it. If a date is stored as text, a relationship is connected incorrectly, or a percentage uses the wrong denominator, the chart can look professional and still mislead a manager.

Your habit: before asking “Does this chart look good?” ask “What exactly is being counted, averaged, divided, or filtered?”

Model accuracy

Wrong data types, duplicate dimension keys, or many-to-many relationships can corrupt measures.

Metric accuracy

A rate must document numerator, denominator, filter context, and units.

Interpretation accuracy

A chart can reveal association or concentration without proving cause or intent.

Healthcare privacy: keep the class dashboard aggregated. Patient identifiers should not be displayed in report visuals. Public administration: equity patterns should be described with evidence without inventing motives.

9. Discussion Preparation

How to explain visualization without sounding technical

For the discussion, imagine you are explaining your dashboard to a manager who does not care about DAX or software menus. Start with the decision, then the evidence, then the visual.

  1. Decision: What does the manager need to decide or investigate?
  2. Evidence: What number or comparison helps answer that question?
  3. Visual: What picture makes the comparison easiest to understand?
  4. Limitation: What could make the result incomplete or misleading?

The Week 6 discussion asks how Power BI or Tableau can turn raw data into strategic insight, and what can undermine the accuracy or relevance of those visuals.
